# Проектирование подсетей VLSM и статическая маршрутизация в Cisco IOS

Лабораторная работа по разбиению адресного пространства `192.168.5.0/24` с использованием масок подсети переменной длины (**VLSM**) от самой крупной подсети к самой маленькой (point-to-point линк), настройке интерфейсов маршрутизаторов `R1` и `R2`, статической маршрутизации между сегментами и проверке сквозной связности между конечными узлами.

## Топология и расчёт подсетей (VLSM)

![Топология сети и схема VLSM](images/настройка%20vsml%20сабсетей.png)

* **Исходная сеть:** `192.168.5.0/24`
* **Среда:** Cisco Packet Tracer
* **Принцип распределения:** подсети выделяются последовательно в порядке убывания требуемого числа хостов (`64 → 45 → 14 → 9 → 2`), чтобы минимизировать потери IP-адресов.

## 1. Настройка маршрутизаторов

### Маршрутизатор `R1`

На `R1` настроены интерфейсы локальных сетей `LAN1`, `LAN2`, транзитный интерфейс `G0/0/0` (в ходе проверки исправлена опечатка в первом октете `198.168.5.x` → `192.168.5.x`) и статические маршруты до удалённых подсетей `192.168.5.192/27` и `192.168.5.224/28` через `R2` (`192.168.5.242`):

```cisco
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 192.168.5.190 255.255.255.192
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 192.168.5.126 255.255.255.128
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ip address 192.168.5.241 255.255.255.252
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# ip route 192.168.5.192 255.255.255.224 192.168.5.242
R1(config)# ip route 192.168.5.224 255.255.255.240 192.168.5.242
```

![Настройка статических маршрутов и исправление адресов на R1](images/настройка%20статических%20маршрутов%20R1%20%2B%20исправления%20адресов%20интерфейсов.png)

### Маршрутизатор `R2`

На `R2` настроены интерфейсы подсетей `LAN3`, `LAN4`, транзитный интерфейс `G0/0/0` и статические маршруты до подсетей `192.168.5.0/25` и `192.168.5.128/26` через `R1` (`192.168.5.241`):

```cisco
R2(config)# interface GigabitEthernet0/0
R2(config-if)# ip address 192.168.5.222 255.255.255.224
R2(config-if)# no shutdown
R2(config-if)# exit

R2(config)# interface GigabitEthernet0/1
R2(config-if)# ip address 192.168.5.238 255.255.255.240
R2(config-if)# no shutdown
R2(config-if)# exit

R2(config)# interface GigabitEthernet0/0/0
R2(config-if)# ip address 192.168.5.242 255.255.255.252
R2(config-if)# no shutdown
R2(config-if)# exit

R2(config)# ip route 192.168.5.0 255.255.255.128 192.168.5.241
R2(config)# ip route 192.168.5.128 255.255.255.192 192.168.5.241
```

## 3. Проверка связности (Ping-тесты)

Для подтверждения корректности расчёта масок и маршрутизации выполнена серия проверок `ping` между всеми подсетями:

1. **`PC1` (`192.168.5.1`) → `PC3` (`192.168.5.193`):** после первичного ARP-разрешения пакеты проходят без потерь (`TTL=126`, два маршрутизатора `R1 → R2`):

   ![Тест 1: пинг PC1 — PC3](images/тест%201%20-%20пинг%20pc1%20-%20pc3.png)

2. **`PC4` (`192.168.5.225`) → подсеть `LAN1` (`192.168.5.129`):** `0% loss`, `TTL=126` (`R2 → R1`):

   ![Тест 2: пинг PC4 — LAN1](images/тест%202%20-%20пинг%20pc4%20-%20pc1.png)

3. **`PC2` (`192.168.5.129`) → шлюз `LAN4` (`192.168.5.238`):** `0% loss`, `TTL=254` (ответ от интерфейса Cisco IOS `R2` через `R1`):

   ![Тест 2: пинг PC2 — R2 G0/1](images/тест%202%20-%20пинг%20pc2%20-%20pc4.png)

4. **`PC2` (`192.168.5.129`) → `R2` (`192.168.5.238`) и соседний сегмент (`192.168.5.129`):** подтверждение маршрутизации через `R1`:

   ![Тест 3: проверка связности с PC2](images/тест%203%20-%20пинг%20pc1%20-%20pc2.png)

5. **`PC4` (`192.168.5.225`) → `PC2` (`192.168.5.129`) и `PC3` (`192.168.5.193`):** подтверждена связность как с удалённой подсетью за `R1` (`TTL=126`), так и с соседней подсетью за `R2` (`TTL=127`):

   ![Тест 4: пинг PC4 — PC2 и PC4 — PC3](images/тест%204%20-%20пинг%20pc4%20-%20pc3.png)
